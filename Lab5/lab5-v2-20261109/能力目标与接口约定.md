# lab5 · 能力目标与接口约定（写时复制 COW fork 与 exec 参数解析）

> **增量包版本**：v2（2026-11-09），由课程组统一发放。

> 本实验基于前序自研内核代码完成两项核心演进：
  第一，将 lab3 的 `uvmcopy` 重构为基于物理页引用计数的写时复制（Copy-on-Write，简称 COW）共享机制；第二，在 lab2/lab3 的 `usertrap`、`copyout` 与 `uvm_check_range` 中扩充写时复制页面分离逻辑，并补齐 `exec` 的命令行参数用户栈装配。

## 1. 能力目标（由你设计并实现）

1. **物理页引用计数与 `kfree` 回收守恒**：为物理内存页维护准确的引用计数（`LAB5_REFCNT_SCHEME`）；`kalloc` 分配时置计数为 `1`，`uvmcopy` 共享时递增计数，`kfree` 递减计数且仅当计数归零时执行 `memset(pa, 0x5a, PGSIZE)` 并归还空闲池。
2. **`fork` 写时复制（COW）与缺页异常细分处理**：`uvmcopy` 将父子进程可写页同时清除 `PTE_W` 并标记 `PTE_COW`（跳过 `PTE_V == 0` 保护页）；`usertrap`（`scause == 15`）、`copyout` 与 `uvm_check_range` 准确区分合法 COW 页面与非法只读/越界写访问，并在 `refcnt == 1` 时原地恢复 `PTE_W` 避免冗余拷贝。
3. **完善 `exec` 系统调用参数栈装配**：从旧地址空间提取 `argv[]` 字符串数组，在新用户栈顶按 16 字节对齐压入字符串与指针数组（含 `argv[argc] = 0` 哨兵），设置 `tf->a1 = sp` 并由 `kexec` 返回 `argc`（经 `syscall()` 写入 `tf->a0`）；确保失败路径无物理内存泄漏。
4. **进程终止语义（`LAB5_KILL_SEMANTICS`）**：收到终止信号时立即终止且不执行复制（`0`），或允许完成当前页面复制后再退出（`1`）。
5. **写时复制配额管理（`LAB5_COW_BUDGET`）**：按单进程统计写缺页实际拷贝次数，达到阈值 `LAB5_COW_BUDGET` 时执行设计笔记约定的容错降级策略（推荐打印一次配额告警后继续运行，确保不破坏 `bench` 多轮并发回归）。

## 2. 接口约定与核心规范

1. **`exec` 接口规范**：完整实现 `exec(name, argv)` 语义（用户态库接口保持不变）；可执行程序映像仍来自内核内嵌程序表（磁盘文件系统在 lab6 中实现）。增量包升级后的 `gifts/user/sh.c` 已支持按空格切分命令行参数，可在 `sh>` 下直接运行 `echo hi` 验证。
2. **内存计数观测接口**：新增系统调用 `pmc(which)` —— 系统调用号 **SYS_pmc = 26**（预置支撑文件已更新，累积 lab4 的 23/24/25 号系统调用）：
   - `pmc(0)` 返回系统自启动以来在写时复制分离中**实际分配新物理页并执行拷贝**的总次数（`uint64`，`refcnt == 1` 原地恢复写权限不计入）；
   - `pmc(1)` 返回当前正处于共享状态（`refcnt > 1`）的物理页总数（`uint64`）。
3. **功能回归测试规范**：lab4 的 `bench`、lab3 的 `badaccess`/`memcap`/`vmtest` 以及 lab2 的串口测试集均须正常通过。

## 3. 设计决策（设计笔记必须明确回答；现场验收重点考查）

- 三种引用计数方案（`LAB5_REFCNT_SCHEME`）的硬件位宽约束、时间复杂度与并发互斥粒度对比；为什么方案 0（PTE 保留位）与方案 2（页表反向扫描）需配合分配器全局 `refcnt[]` 数组才能安全完成 `kfree(pa)`。
- 物理页引用计数增加与减少的四个关键场景（`kalloc` 分配、`uvmcopy` 共享、`cow_alloc` 分离、`uvmunmap`/`kfree` 解映射）分别对应哪几处代码。
- 双核（`-smp 2`）下两个进程同时对同一 `refcnt == 2` 页面触发写缺页时，如何保证先写方拷贝 1 次、后写方命中 `refcnt == 1` 原地恢复而不发生重复拷贝。
- `fork` 后立即执行 `exec` 时的物理页复制读数预期：为什么读数不超过 2（实测为 1）。
- 引用计数丢失一次增减操作或未加锁并发修改所导致的系统故障链推演。

## 4. 预置支撑代码（`gifts/`）

- `gifts/kernel/syscall.h`、`gifts/user/user.h`、`gifts/user/usys.pl`：新增 `SYS_pmc = 26` 调用号与用户态桩代码。

- `gifts/Makefile.upgrade`：`UPROGS += zerocopy cowpair echo` 内嵌构建接入片段。

## 5. 里程碑自检

1. **阶段一自检**：编写分配、共享递增、逐次释放的内核自测函数，确认空闲物理页数与引用计数严格守恒。
2. **阶段二与阶段三联合自检**：完成 `uvmcopy`、`cow_alloc`、`copyout`/`uvm_check_range` 与 `sys_pmc` 后，运行 `cowpair` 输出 `T5-2 copies delta = 2 (expect 2)` 与 `T5-2 PASS`。
3. **阶段四自检**：运行 `zerocopy` 输出 `T5-1 PASS`（`delta <= 2`）；在 `sh>` 下运行 `echo hi` 输出 `hi` 与 `T5-3 PASS: argc=2 argv[0]=echo aligned`。
4. **综合与回归测试**：验证只读代码段写保护、配额降级告警与 `bench`/`memcap` 回归测试全部通过。

## 6. 交付测试程序（已随包提供于 `support/tests/`）

- `zerocopy.c`：针对 `fork` 后立即 `exec` 场景的零复制断言测试（页面复制增量 $\le 2$ 判定为通过）；
- `cowpair.c`：配对写入与内存引用对账测试（验证共享计数大于 0、进程间数据完全隔离、栈页与堆页合计触发恰好 2 次页面复制）；
- `echo.c`：校验 `exec` 用户栈 `argc`/`argv` 装配、NULL 结尾哨兵与 `argv` 16 字节对齐。
  使用方法详见 `support/tests/README-tests.md`。
