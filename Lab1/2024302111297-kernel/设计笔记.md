## 核心问题简答

1. 上电后 PC=0x1000，QEMU 的 -bios none 意味着什么？内核为何必须链接到 0x80000000 而非 0x0？

上电后 PC 是 `0x1000`，这是 QEMU 的复位入口。`-bios none` 表示不使用 OpenSBI 等固件，所以要由内核自己完成早期初始化。内核链接到 `0x80000000`，因为 QEMU `virt` 机器的 RAM 从这里开始，`0x0` 不是可用内核内存。

2. entry.S 里每条指令的存在理由：为什么第一步要关中断？初始内核栈设在哪里、分配多大、为什么？为什么 mhartid != 0 的从核必须进入自旋等待（park）？陷阱向量基址寄存器（mtvec）的写入值有什么对齐要求？

`entry.S` 先关中断，是因为栈、trap 入口等还没准备好。启动栈放在内核静态空间里，本实验为 8KB，设置 `sp` 到栈顶。只让 `mhartid == 0` 的主核继续执行，其他从核进入 `wfi` 等待，避免多核同时初始化产生冲突。`mtvec` 写入的 trap 入口至少要 4 字节对齐。

3. 进入 S 态前必须完成的配置清单：mstatus.MIE 状态、mepc 目标、中断委托（delegation）、以及 PMP 物理内存保护配置（见下方必读环境前置条件）。

进入 S 态前，需要设置 `mstatus.MPP = S`，让 `mret` 返回到 S 态；设置 `mepc = main`，指定 S 态入口；配置 `medeleg/mideleg`，把异常和中断交给 S 态处理；配置 PMP，给 S 态开放物理内存访问权限。启动切换时一般保持中断关闭，等内核准备好后再打开。

4. 启动阶段 satp 寄存器选择"直接禁用（Bare 模式）"还是"恒等映射"？给出你的设计决策与论证。

启动阶段我选择 `satp = 0`，也就是 Bare 模式。因为这时还没有建立页表，内核本来就运行在物理地址 `0x80000000` 上，直接禁用分页最简单可靠。等以后实现虚拟内存时，再切换到页表映射。

5. UART 16550 轮询输出协议：涉及哪些寄存器、哪个状态标志位、在什么条件下才能向发送保持寄存器写字符？

UART 16550 轮询输出时，先读 LSR 线路状态寄存器，检查 bit5，也就是 `0x20`。只有该位为 1，说明 THR 发送保持寄存器为空，才能把字符写入 THR。否则要一直等待，避免覆盖还没发送完的字符。

## 1. 实验目标

本实验实现一个最小 RISC-V 裸机内核启动流程：

1. QEMU 将内核加载到 `0x80000000` 后，从 `_entry` 开始执行。
2. `_entry` 关闭机器态中断，读取 `mhartid`，让 0 号 hart 初始化栈并进入 `start()`；其他 hart 停在 `wfi` 循环。
3. `start()` 配置 M 态到 S 态切换所需的 `mstatus`、`mepc`、`satp`、委托寄存器和 PMP，然后执行 `mret`。
4. S 态执行 `main()`，初始化串口，使用轮询方式输出个人 banner。

本人的 `COURSE_SID % 3 = 1`，因此输出协议为每个实际输出字节后紧跟一个 `.`。

## 2. 启动时序

```text
QEMU PC=0x1000
    |
    | -bios none 时，QEMU 不提供固件启动程序，-kernel 将内核装入 RAM
    v
0x80000000: _entry，M 态
    |
    | 关闭 mie；非 0 号 hart 进入 park
    | 设置 boot_stack 顶端为 sp，容量为 LAB1_STACK_KB=8KB
    v
start()，M 态
    |
    | mstatus.MPP = S
    | mepc = main
    | mtvec = 对齐的 machine_trap_vector
    | satp = 0，使用 Bare 模式，不启用页表
    | medeleg/mideleg 委托异常和中断
    | PMP NAPOT 放行物理地址空间
    v
mret
    |
    v
main()，S 态
    |
    v
UART 轮询输出 banner
```

## 3. 为什么链接到 0x80000000

QEMU `virt` 机器的 RAM 从物理地址 `0x80000000` 开始，且 `-kernel` 会把内核装载到该地址。链接脚本中的 VMA 必须和实际加载地址一致，否则 `_entry`、跳转目标和全局数据地址会不一致。`0x0` 是 QEMU 的低地址区域，不是内核 RAM 的起始位置。

`-bios none` 表示不加载 OpenSBI 等固件，QEMU 直接按照机器约定把内核装入 RAM 并跳转到内核入口；因此本实验必须自己完成早期机器态准备。

## 4. entry.S 中的设计理由

- `csrw mie, zero`：启动早期没有准备好中断处理环境，先关闭机器态中断。
- `csrr a0, mhartid`：识别当前 hart。
- `bnez a0, park`：本实验只让 0 号 hart 启动，避免多个 hart 同时写串口和共用启动栈。
- `la sp, boot_stack` 加上 `LAB1_STACK_KB << 10`：栈向低地址增长，因此 `sp` 从栈空间末端开始。个人参数要求为 8KB。
- `wfi` 加跳转：从核低功耗等待，不进入 C 代码。
- `.balign 4`：`mtvec` 要求至少 4 字节对齐，否则写入的陷阱入口地址可能无效。

## 5. M 态到 S 态的配置

- `mstatus.MPP = MSTATUS_MPP_S`：让 `mret` 返回到 S 态。
- `mepc = main`：指定返回后的第一条指令。
- `mtvec = machine_trap_vector`：为 M 态异常提供对齐入口。
- `satp = 0`：启动阶段没有页表，使用 Bare 模式，虚拟地址直接按物理地址解释。
- `medeleg/mideleg`：把常规异常和中断委托给 S 态；本实验暂未打开 S 态中断。
- `pmpaddr0 = 0x3fffffffffffff`、`pmpcfg0 = 0xf`：NAPOT 模式、读写执行权限全部打开，使 S 态可以访问 QEMU 提供的物理地址空间。

如果缺少 PMP 配置，现代 QEMU 中 `mret` 进入 S 态后可能在第一条取指处触发 instruction access fault，表现为串口完全无输出。

## 6. UART 轮询协议

QEMU `virt` 的 UART 基地址是 `0x10000000`：

- THR 偏移 `0`：发送保持寄存器。
- LSR 偏移 `5`：线路状态寄存器。
- LSR bit5，也就是 `0x20`：THR 空，可以发送下一个字节。

`uartputc_raw()` 循环等待 `LSR & 0x20` 非零，再把字符写入 THR。`consputc()` 在硬件发送外包一层协议：本人的协议为 1，所以原始字节发送后立即再发送 `.`。

节流周期使用 `16 + (COURSE_SID % 16)`，并引用学号宏计算，达到周期后执行 nop 循环。

## 7. printf 约定与测试边界

实现支持 `%d`、`%u`、`%x`、`%p`、`%s`、`%c` 和 `%%`：

- 十进制负数输出负号，不输出前导零。
- 十六进制使用小写 `0123456789abcdef`，不输出前导零。
- `%s` 遇到空指针输出 `(null)`，空字符串输出零个正文字符。
- 整数 0 使用 do-while，保证输出一个 `0`。
- 长字符串逐字节输出，不使用固定长度临时缓冲区。

启动 banner 的期望输出记录在 `expect_banner.txt`，该文件末尾必须是协议 1 的 `.`，不能多一个换行。
